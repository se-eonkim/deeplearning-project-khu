# 🟧 폰 담당: 실제 폰 데이터 수집 + 모델 적용 + 데모 영상

**역할:** 우리 폰으로 센서 데이터를 찍는다. 그 데이터를 UCI와 같은 모양으로 바꿔서 팀 모델에 넣고 행동을 맞힌다. 결과는 녹화 영상으로 발표한다. **발표의 핵심 장면을 맡는다.**

**원칙:** 모델은 UCI 데이터만 보고 학습했다. 우리 폰 데이터는 **UCI와 똑같은 모양**(단위, 속도, 방향, 채널 순서, 정규화)이어야 맞힌다. 하나라도 다르면 에러 없이 엉뚱한 답이 나온다.

> 시작 전에 [레포 README](../README.md)의 협업 규칙과 [`shared/README.md`](../shared/README.md)의 약속(채널 순서, 정답 형식)을 먼저 읽는다.

## 1단계. 프로젝트와 센서 이해

**자료:** [레포 README](../README.md) 1~3절 · [UCI HAR 페이지](https://archive.ics.uci.edu/dataset/240/human+activity+recognition+using+smartphones) · [UCI README 원문](https://huggingface.co/datasets/udayl/UCI_HAR/blob/main/README.txt) · [안드로이드 센서 좌표계 설명](https://developer.android.com/guide/topics/sensors/sensors_overview)

| 알아야 할 것 | 내용 |
|---|---|
| 모델 입력과 출력 | 입력은 센서값 2.56초치(50Hz × 128시점 × 6채널 = 768), 출력은 6가지 행동 |
| UCI 데이터 모양 | [zip 다운로드](https://archive.ics.uci.edu/static/public/240/human+activity+recognition+using+smartphones.zip) 후 `train/Inertial Signals/` 폴더를 직접 열어 본다. 파일 9개, 한 줄에 숫자 128개 = 샘플 하나 |
| **가속도계** | 움직임 + **중력**을 잰다. 가만히 있어도 아래쪽 축이 약 9.8(= 1g)을 가리킨다 |
| **자이로** | 회전 속도를 잰다. 가만히 있으면 거의 0 |
| **중력 = 폰의 기울기** | 서기와 눕기는 중력이 다른 축에 실린다. 모델은 이걸로 자세를 구분한다 → **폰 방향이 바뀌면 자세 판단이 전부 틀린다** |

## 2단계. phyphox 세팅

**자료:** [phyphox 공식 사이트](https://phyphox.org/) (폰 센서를 기록하고 CSV로 내보내는 무료 앱)

| 할 일 | 신경 쓸 것 |
|---|---|
| 앱 설치, **중력 포함 가속도**("Acceleration with g")와 **자이로** 실험 찾기 | "without g"(중력 제외)를 고르면 안 된다. 우리 모델은 `total_acc`(중력 포함)를 쓴다 |
| 둘을 한 번에 기록할 수 있는지 확인 | 안 되면 따로 기록한다. 이때는 **시작할 때 폰을 세게 3번 흔들기**. 두 파일의 흔든 지점을 맞춰서 시간을 맞춘다 |
| 10초 테스트 기록 → CSV 내보내기 → 노트북에서 열기 | CSV에서 확인: **시간 단위**(초/밀리초), **가속도 단위**(m/s²), **자이로 단위**(rad/s / deg/s, UCI는 rad/s), **1초에 몇 번 찍히는지**(UCI는 50) |
| 측정 간격 확인 | 간격이 **일정하지 않은 게 정상**이다. 그래서 5단계에서 시간 기준으로 다시 뽑는다 |

## 3단계. 착용 방향 맞추기 ★ 가장 중요

| 할 일 | 신경 쓸 것 |
|---|---|
| **UCI 서 있을 때 평균 직접 구하기:** `total_acc_x/y/z_train.txt` 중 `y_train.txt`가 5(STANDING)인 줄만 골라 x, y, z 평균 | 이 값이 방향 확인의 **정답지**다. 모델은 UCI로 "서 있을 때는 이 축에 중력이 이만큼"을 배웠다. 정규화 전 원래 값(g 단위)으로 구한다 |
| 허리 벨트에 고정. 시작점은 **화면은 바깥, 폰 위쪽은 머리 방향** | 흔들리면 안 된다. 주머니는 금지 (방향이 매번 바뀜) |
| **착용 사진** 찍기 (얼굴 안 나오게) | 앞으로 모든 기록을 이 방향으로 한다 |
| 차고 가만히 서서 30초 기록 → 가속도 x,y,z 평균 → **÷ 9.80665로 g 변환** → UCI 값과 비교 | 세 축 값이 비슷하면 통과 (특히 **어느 축이 약 ±1g인지**와 **부호**) |
| 다르면 폰 방향을 바꿔서 다시 | 축이 바뀐 것뿐이면 코드에서 축을 바꿔 끼워도 된다. **고친 방법을 기록**한다 |
| 팀원이 각자 폰을 쓰면 **폰마다** 확인 | 기종이나 OS가 다르면 축 방향이 다를 수 있다 |

> ⚠️ **나를 기다리는 사람:** 방향 확인 결과를 **바로 팀에 공유**한다. 방향이 틀린 채로 찍으면 전부 다시 찍어야 한다.

## 4단계. 데이터 수집

| 할 일 | 신경 쓸 것 |
|---|---|
| 6가지 행동 각 1~2분 기록 | **파일 하나에는 행동 하나만** 담는다. 파일 이름이 곧 정답이다 (`phone/raw/walking_p1_1.csv`) |
| 걷기, 계단 오르기, 계단 내려가기 | 계단은 실제 계단에서, **오르기와 내려가기를 따로** 기록한다 |
| 앉기, 서기, 눕기 | 앉기는 의자, 눕기는 **반듯이 누워서**. 자세를 바꾸는 순간은 기록에 넣지 않는다 |
| **영상 동시 촬영** (발표 재료) | 시작할 때 **손뼉 한 번** → 영상과 센서 데이터의 시작점을 맞춘다 |
| 가능하면 팀원 2~3명 기록 | 사람이 다르면 결과가 달라지는 것도 분석 재료다 |
| | **영상과 얼굴 사진은 레포에 올리지 않는다** (공개 레포). CSV만 올린다 |

## 5단계. UCI 모양으로 변환

| 순서 | 할 일 | 신경 쓸 것 |
|---|---|---|
| 1 | 앞뒤 3초 자르기 | 폰 넣고 빼는 동작, 흔들기, 손뼉 구간 제거 |
| 2 | 가속도 ÷ 9.80665 (m/s² → g) | 자이로가 deg/s면 × π/180 |
| 3 | 50Hz 리샘플링 ([`np.interp`](https://numpy.org/doc/stable/reference/generated/numpy.interp.html)) | **시간축 기준**으로 0.02초 간격 새 시간축을 만들고 축마다 보간한다. 샘플을 몇 개씩 건너뛰는 방식은 금지 (간격이 불규칙해서 틀어짐) |
| 4 | 128개씩 자르기, 64개씩 겹치게 | UCI와 같은 방식. 예측은 **1.28초마다** 하나씩 나온다 |
| 5 | 채널 순서: `total_acc x,y,z → body_gyro x,y,z` | **[`shared/README.md`](../shared/README.md)의 순서**를 따른다 |
| 6 | 정규화 | 데이터 담당의 **`shared/norm_stats.npz`(UCI 학습 데이터 통계)**로 한다. **폰 데이터 자체 평균 금지** (기울기 정보가 사라지고, UCI 기준과 어긋남) |
| 7 | 펼치기 → `(N, 768)` | **데이터 담당의 펼치기 함수를 그대로** 쓴다. 직접 `reshape`하면 순서가 어긋날 수 있다 |

1~5번은 모델 없이 지금 할 수 있다.

> ⚠️ **내가 기다리는 것:** 6~7번은 데이터 담당의 `shared/norm_stats.npz`와 펼치기 함수가 있어야 한다.

## 6단계. 예측과 평가

| 할 일 | 신경 쓸 것 |
|---|---|
| 모델 담당의 **`shared/weights.npz`(조건 ⑤ 모델)**로 예측 | 6채널 모델이어야 한다. 다른 조건 모델은 입력 크기가 다르다 |
| **혼동행렬** (행=정답, 열=예측) | 데이터 담당과 같은 형식: **행별 비율**, 같은 행동 순서 |
| UCI 테스트 정확도(조건 ⑤)와 나란히 비교 | 숫자보다 **어떤 행동이 무엇으로 틀렸나**를 본다 |
| 틀린 행동마다 이유 적기 | 후보: 방향 / 단위 / 기종 / 사람 / UCI만 노이즈 필터를 거침 / 착용 위치 |
| 변환된 폰 데이터 `(N, 768)` + 정답을 `phone/`에 올리기 | 모델 담당이 은닉공간 분석("왜 틀렸나" 그림)에 쓴다 |

> ⚠️ **내가 기다리는 것:** 모델 담당의 `shared/weights.npz`.
> ⚠️ **나를 기다리는 사람:** 모델 담당의 은닉공간 분석이 변환된 폰 데이터를 기다린다.

## 7단계. 발표 영상

| 할 일 | 신경 쓸 것 |
|---|---|
| 행동 영상 옆에 **1.28초마다 예측 행동** 표시 | 손뼉 지점으로 영상과 예측의 시간을 맞춘다 |
| 맞은 장면과 틀린 장면을 **둘 다** 넣기 | 틀린 장면에는 6단계의 이유를 자막 한 줄로 단다 |
| 길이는 1~2분 | 6가지 행동이 다 나오게 |

## 발표 담당 파트
1. **폰 데모 영상 (핵심)**
2. 폰 데이터를 UCI 모양으로 맞춘 과정: 단위, 속도, 방향
3. **"UCI에서는 잘 맞는데 폰에서는 왜 틀렸나?"** → 6단계의 이유 표로 답한다 (모델 담당의 은닉공간 그림으로 이어짐)
